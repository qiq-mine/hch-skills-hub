# Maintain a verification skill

A feature map rots the moment the app changes. This skill is the upkeep loop for a skill generated by `/create-verification-skill` (or any project-local verification skill with a feature map). The unit of rigor is the feature: cover every feature file from source and exercise every feature live.

## Outcomes

Pick one and state clearly:
- **clean** — every feature got source and live coverage; nothing worth changing.
- **changed** — one PR or commit ships proven doc, harness, or map corrections.
- **blocked** — coverage could not finish or a proven fix could not ship safely. Say exactly what blocked it.

## Edit scope

Only edit the verification skill's own directory (its SKILL.md, features/, and harness scripts). Never edit product code during a maintenance pass: behavior divergence is either doc drift (fix the map) or product regression (report it).

## Pass

0. **Locate the target.** Find the verification skill to maintain (usually `.agents/skills/verify-*/` or `skills/verify-*/`).
1. **Index hygiene.** Read the feature map README and index files. Fix missing or broken links.
2. **Source wave.** Spawn read-only subagents (in Antigravity: `invoke_subagent` with `TypeName: "research"`) per feature file. Each explores how the feature works from source, flags likely drift with citations, and returns a concise live recipe.
3. **Reconcile.** Merge summaries, verify cited drift, and detect newly added user surfaces missing from the map.
4. **Live pass.** The coordinator executes the live pass following the skill's Launch model. Doctor check before driving, exercise each feature, capture evidence, and clean up afterwards.
5. **Triage.** Fix doc drift or harness gaps. If app behavior is broken, record it for the user as an issue.
6. **Ship or report.** For changed, commit proven corrections. For clean or blocked, report results honestly.
