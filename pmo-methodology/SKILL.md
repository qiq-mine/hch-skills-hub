# 杰诺软件项目实施方法论

> 来源：广东杰诺软件项目管理规范 V1.3（20230411）
> 适用：企业信息化（ERP等）项目实施交付全过程

## 三大指导原则

1. **客户为中心** — 深刻理解客户需求，定义并管理客户组织级满意度，服务一线拉动流程，客户价值可衡量
2. **专业化** — 成果优秀、组织保障、能力胜任；不囿于通用方案，从客户真实需求出发
3. **标准化** — 成果标准化 + 过程标准化；以 CMMI3/ITSS3 为参考，持续修正完善

## 实施主流程概览

```
项目准备 → 项目启动 → 业务蓝图 → 系统实现 → 系统上线 → 项目验收
```

每个阶段均包含：**定义 → 任务 → 内容 → 说明 → 风险及应对 → 过程标准文档 → 重要文档管理**

## 实施六阶段速查

### 阶段 1：项目准备

**定义**：商务确认后、项目启动前，了解售前过程，分析已承诺的目标/范围/计划/风险，为实施策略做准备。

**核心任务**：建立项目组织 + 售前资料移交

**关键文档**：项目组织结构、项目经理任命书、团队任命书、SOW、WBS、里程碑计划、7key项目评估、关键干系人清单、项目合同

**主要风险**：
- 售前交接不清 → SOW 交接须项目经理+蓝图顾问+销售经理+售前顾问共同完成
- 资源匹配不当 → 科学拆解 WBS，评估能力素质与时间要求

**项目组织架构三层**：领导层（总经理/副总）→ 管理层（双方项目经理）→ 执行层（实施人员）

**重要文档质量标准**：
- SOW：关注客户价值、易读、表述清晰无二义、可落地；售前编写→销售评审→方案总监审核→客户签字
- WBS：客户价值第一、可落地、可检查、工作量可衡量、标准化；与 SOW 同保障制度

> 详见 [phases-reference.md](phases-reference.md) §项目准备

---

### 阶段 2：项目启动

**定义**：项目准备后、蓝图前，正式启动准备工作。

**核心任务**：内部立项 + 客户首次拜访 + 入场筹备 + 启动大会 + 系统部署

**关键文档**：项目立项报告、调研计划、实施主计划、项目章程、奖惩绩效制度、启动大会议程/PPT、产品安装确认单

**主要风险**：
- 范围界定不清 → 项目经理+蓝图顾问须对目标/范围清晰认知
- 实施策略缺失 → 考虑干系人、产品范围、上线业务范围、开发因素
- 客户方项目经理不合适 → 售前即引导，筹备期协商
- 包办客户组织过程 → 顾问指导而非越俎代庖
- 不安排客户参与准备 → 保持密切协作，抓住客户兴奋期
- 计划不合理 → 预留风险时间，考虑多团队协作

**项目章程必含**：项目组织、沟通机制（日报/周例会/月例会/专题会）、决策机制、计划管理、需求方案管理、风险管理

**项目计划体系**：里程碑计划 → 主计划 → 专题明细计划 → 双周滚动计划 → 个人周计划

> 详见 [phases-reference.md](phases-reference.md) §项目启动

---

### 阶段 3：业务蓝图

**定义**：启动后、实现前，调研分析业务流程，优化并设计蓝图方案。

**核心任务**：
1. **调研分析** — 高层培训 → CRP测试 → 现场调研 → 高层访谈 → 调研报告
2. **蓝图设计** — 流程优化 → 蓝图与产品匹配 → 蓝图方案 → 内部评审评分 → 客户确认签字
3. **需求分析** — 开发概要 → 开发评估 → 需求规格说明书 → 评审评分 → 确认签字

**关键文档**：调研计划/问卷/签到表/纪要/报告、蓝图设计/评分表/确认单、开发概要/需求分析/评分表/确认单

**蓝图质量标准**：
- 客户价值导向：理解经营现状与战略、符合信息化需求、专业性、充分沟通、知识传递
- 可落地性：考虑人员现状、技术可行且预算可控、与合同产品范围匹配、可读性
- 组织保障：蓝图顾问编写 → 售前+实施团队评审 → 方案总监+项目经理审核 → 客户签字

> 详见 [phases-reference.md](phases-reference.md) §业务蓝图

---

### 阶段 4：系统实现

**定义**：蓝图后、上线前，系统设计、开发、测试、数据初始化、培训。

**核心任务**：开发设计 → 编码 → 功能测试 → 系统配置 → 数据初始化 → UAT测试 → 关键用户培训 → 操作手册编写 → 最终用户培训 → 真实数据模拟

**关键文档**：设计文档、测试用例/报告、系统配置清单、数据收集方案/计划/检查表、UAT全套文档、培训计划/PPT/考核表、操作手册

**主要风险**：
- 前期蓝图偏离实际 → 直接影响系统模拟上线
- 实施主次不分 → 保证主要实施对象优先
- 培训不到位 → 确保培训质量并严格考核
- 客户人员不到位 → 加强人员组织
- 数据准备有误 → 签字确认，及时整改

**UAT测试双重目标**：① 检验系统质量（真实场景/数据/环境）② 培训练兵（上线前对人员充分培训）

**设计文档质量标准**：承接业务方案（理解蓝图目标初衷）+ 统领功能开发（整体设计抽象，降低开发难度）

> 详见 [phases-reference.md](phases-reference.md) §系统实现

---

### 阶段 5：系统上线

**定义**：实现后、验收前，上线方案、模拟测试、切换、支持。

**核心任务**：上线规划 → 系统切换 → 上线支持 → 上线总结

**关键文档**：上线方案、上线评估清单/执行表、上线动员大会PPT、上线通知、系统上线确认单、问题清单、上线问题总结报告

**上线方案必含**：上线计划/范围、运行环境、上线准备（技术/业务/安全）、系统切换步骤、应急方案、运行支持方式、问题处理流程

**切换计划要点**：
- 考虑风险/备选方案/数据备份，支持回滚
- 负责人为业务主管领导
- 以小时为单位，明确校验时间
- 明确顾问 vs 关键用户 vs 实施方职责
- 运行支持：关键用户→最终用户，顾问→关键用户

> 详见 [phases-reference.md](phases-reference.md) §系统上线

---

### 阶段 6：项目验收

**定义**：系统运行达预期后，文档整理、验收报告、总结大会、转运维。

**核心任务**：整理文档编写验收报告 + 总结大会 + 转运维交接

**关键文档**：系统验收报告、验收备忘录、项目总结报告PPT、实施完成确认单、实施转服务交接

**项目总结报告质量标准**：
- 总结项目价值：目标达成情况、对企业提升、经济性评价（时间/成本）、论功行赏
- 总结管理经验：各阶段优秀/待改善之处、未来改善空间
- 组织保障：项目经理牵头+蓝图顾问 → 售前+销售评审 → 方案总监+项目总监审核

**主要风险**：
- 文档不完整/不规范 → 每周/月末检查
- 人员变动致文档收集困难 → 重视文档重要性，变动时检查交付
- 客户不确认阶段成果 → 及时沟通解决，勿拖至验收
- 客户对验收持怀疑态度 → 验收前充分沟通遗留问题
- 商务关系冷淡 → 上线阶段加强客户关系沟通

> 详见 [phases-reference.md](phases-reference.md) §项目验收

## 项目管理公约速查

六大管理领域，每个领域均按 **定义 → 规则 → 检查 → 考核** 结构执行。

### 1. 范围管理

以 WBS 为基线，禅道系统管控任务。

**核心规则**：
- 立项后 WBS 基线化，项目组不得私自修改
- 成员不得超出 WBS 私自承诺范围变更
- 范围调整必须走变更流程，同步调整主计划/WBS/禅道任务
- 开发范围调整须同步更新开发概要/需求/设计/测试用例

**检查节点**：蓝图确认+上线两个里程碑由项目经理在禅道检查；每周项目例会检查个人周计划

### 2. 计划管理

计划体系：里程碑计划 → 主计划 → 专题计划 → 双周滚动计划 → 个人周计划

**核心规则**：
- 里程碑计划与商务收款/进度考核挂钩
- 双周计划每周五至下周一邮件发出，抄送存档邮箱
- 个人周计划每周一填报、周末汇报
- 执行偏差通过项目进度看板监控，项目经理每周差异分析

**闭环原则**：计划↔执行检查闭环；主计划↔专项计划闭环；主计划/专项计划↔双周计划闭环

### 3. 变更管理

以 WBS/项目章程/蓝图方案/需求规格说明书的确认作为确认节点，后续不符均走变更流程。

**核心规则**：
- 变更须提交纸质《变更申请单》，客户项目经理签字盖章
- 变更申请在管理系统发起，项目决策委员会审批
- 范围变更界定由项目经理确认，工作量由方案专家+开发PM评估
- 涉及商务由销售部跟进

### 4. 风险管理

使用《7key项目风险评估表》结构化识别分析。

**分级处理**：
- 低级风险 → 项目经理协商解决
- 中级及以上 → 上报双方项目总监
- 高级别（严重）→ 上报项目领导小组，专题会议决策

### 5. 质量管理

构建质量保证体系，形成问题处理→分析总结→优化闭环。

**核心规则**：
- 蓝图/需求评审通过禅道 BUG 跟进，BUG 必须关联项目任务
- 设计/编码质量通过禅道 BUG 跟进
- 过程文档按统一标准格式
- 里程碑节点输出缺陷密度报告

### 6. 沟通管理

**核心规则**：
- **日会**：不驻场时执行经理与顾问团队日会，整理《日汇报》发出
- **周例会**：双方PM+执行经理+关键用户参加，基于双周计划沟通，结论通过周报发出
- **会议规范**：明确主题→形成结论→跟踪事项→会议纪要邮件确认
- **问题跟踪**：立项后建立《项目问题跟踪表》，明确跟踪人/责任人/完成时间

> 详见 [management-protocols.md](management-protocols.md) 获取完整规则/检查/考核对照表

## 使用指南

### 规划新项目时

1. 确定项目所处阶段
2. 查阅对应阶段的任务清单和文档列表
3. 按重要文档管理要求把控质量
4. 识别该阶段风险并制定应对

### 编写项目文档时

1. 确认文档所属阶段
2. 查阅该文档的质量标准和组织保障要求
3. 按标准化格式撰写

### 进行项目健康检查时

1. 对照六大管理公约的规则逐项检查
2. 查看检查节点和考核标准
3. 输出偏差项和改进建议
